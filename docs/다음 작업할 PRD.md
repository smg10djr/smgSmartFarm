1. 배경
수온 센서에서 MQTT, Rails, DB, 실시간 화면, 수온 이상 알림까지 한 줄은 구현되어 있고, 자동 테스트 22건은 통과합니다. 수동 테스트에서 실시간 화면 갱신 2건이 문서와 다르게 동작했고, 환경 구성과 문서에서도 막히는 곳이 나왔습니다. 11월 말 "첫 수확 + 수온 센서 → 화면 → 알림 한 줄 완성"을 위해, 먼저 이 한 줄의 신뢰성을 높이고 실물 ESP32까지 확인해야 합니다.

2. 목표
문서대로 따라 했을 때 1~4단계가 모두 문서와 같게 동작한다.
장치가 처음 나타나는 순간과 알림이 처음 생기는 순간도 새로고침 없이 화면에 반영된다.
처음 설치하는 사람이 Windows(WSL2) 환경에서 막히지 않는다.
실물 ESP32로 5단계(센서 없이)를 확인하고, 6단계(실제 수온 센서)로 넘어갈 준비를 한다.
3. 비목표
220V 직접 제어, pH·EC 자동 주입 (plan.md에서 보류)
명령·ACK, Jev 판단 보조, 물류 시뮬레이터 (이후 선택 과제)
온습도·조도·수위 센서의 실물 연동 (12월 중순 목표, 이번 범위 밖)
4. 작업 목록
우선순위: P0 = 동작 오류, P1 = 설치·운영 걸림돌, P2 = 확인·보강.

P0-1. 첫 장치가 새로고침 없이 나타나지 않음
현상: 장치가 하나도 없는 화면에서 bin/fake_sensor를 실행하면 DB에는 저장되지만 화면은 그대로이고, 새로고침해야 카드가 보입니다. 카드가 이미 있을 때는 실시간 갱신이 됩니다.
원인(추정): show.html.erb는 장치가 없으면 안내 문구만 그리고, DashboardBroadcaster는 dom_id(device)를 대상으로 broadcast_replace_to를 하므로 교체할 요소가 없습니다.
관련 파일: server/app/views/dashboard/show.html.erb, server/app/services/dashboard_broadcaster.rb, server/app/views/dashboard/_device.html.erb
완료 조건:
장치가 없는 화면을 연 채 첫 메시지를 보내면 새로고침 없이 카드가 나타난다.
같은 시점에 "수신된 장치가 없습니다" 문구는 사라지고 pH·EC 입력 폼이 나타난다. (현재 폼은 장치가 있을 때만 그려집니다)
위 동작을 확인하는 테스트(컨트롤러 또는 브로드캐스터)가 있다.
P0-2. 새 알림이 처음 생길 때 목록이 갱신되지 않은 1회
현상: 처음 26.5℃를 보냈을 때 카드의 수온은 바뀌었는데 알림 목록은 "알림이 없습니다"로 남았고 새로고침 후 보였습니다. 이후 두 번(해제, 새 알림)은 실시간으로 반영되어 재현되지 않았습니다.
확인할 가설: 알림 생성과 브로드캐스트의 순서, 또는 빈 상태에서 첫 알림일 때만 생기는 문제. 원인은 아직 모릅니다.
관련 파일: server/app/jobs/ingest_sensor_reading_job.rb, server/app/services/water_temperature_alert.rb, server/app/views/dashboard/_alerts.html.erb
완료 조건:
알림이 하나도 없는 DB에서 첫 알림이 생기는 경우를 재현하는 절차 또는 테스트가 있다.
원인이 확인되고, 같은 절차에서 알림이 실시간으로 표시된다. 재현이 끝내 안 되면 그 사실을 기록하고 닫는다.
P1-1. 호스트 5432 포트 충돌
현상: PostgreSQL이 이미 설치된 PC에서는 compose의 postgres가 127.0.0.1:5432 바인딩에 실패합니다. 이 PC에서는 저장소 밖 override와 PGPORT=5433으로 우회했습니다.
제안: infra/docker-compose.yml의 포트를 환경변수(예: POSTGRES_PORT, 기본 5432)로 바꾸고, server/config/database.yml이 같은 값을 읽게 한다. .env.example에 항목과 설명을 추가한다.
완료 조건: .env에서 포트만 바꿔도 compose와 Rails가 함께 그 포트를 쓴다. 기본값은 지금과 같다.
P1-2. 설치·실행 문서 보완 (docs/testing.md)
Docker Desktop의 WSL integration이 꺼져 있으면 Ubuntu에서 docker 명령이 없다는 증상과 확인 방법
PowerShell에서 Ubuntu용 명령(&& 등)을 실행하면 오류가 난다는 주의. wsl -d Ubuntu -- bash -c "..." 사용법
WSL에서 bin/rails server를 띄울 때 Windows 브라우저가 접속하려면 -b 0.0.0.0이 필요할 수 있는지 확인 후 반영 (이 PC에서는 -b 0.0.0.0으로 실행했고, 이것이 필수인지는 확인하지 않았습니다)
2단계 예시의 measuredAt(2026-10-03T12:00Z 등)이 미래 시각이면 "최근 24시간" 그래프에서 빠질 수 있으므로, 현재 시각을 쓰는 방법을 안내
완료 조건: 위 항목이 반영되고, 처음 설치하는 사람이 같은 문서만으로 1단계까지 도달한다.
P1-3. 구독자 로그 확인
현상: 문서는 터미널 B에 duplicate/rejected 로그가 보인다고 하지만, 이 PC에서는 출력이 비어 있었습니다. 로그가 Rails.logger로 가는 것은 코드에서 확인했지만, 터미널에 나오는지는 확인하지 못했습니다. 출력 버퍼링 때문일 수 있다고 추정할 뿐입니다.
완료 조건: 터미널에서 직접 실행했을 때 subscribed, stored, duplicate, rejected 로그가 보이는지 확인한다. 안 보이면 코드나 문서를 고친다.
P1-4. 오류 문구 한국어화
현상: pH 범위 초과 시 Ph must be in 0..14가 영어 원문으로 표시됩니다. 나머지 화면 문구는 한국어입니다.
제안: config/locales에 한국어 오류 문구를 추가하거나 모델 검증 메시지를 명시한다.
완료 조건: pH 15, EC 범위 초과 입력에서 한국어 문구가 나온다.
P2-1. 시험하지 못한 항목 확인
5분 넘게 수신이 없을 때 카드가 "오프라인"으로 보이는 동작 (Device#online?)이 자동 테스트로 덮여 있는지 확인하고, 없으면 추가한다.
그래프에 선이 그려지는지를 실제로 확인한다. 시간 간격이 있는 데이터로 시험하고, 안 그려지면 원인을 조사한다.
완료 조건: 두 항목의 확인 결과가 docs/testing.md나 테스트에 남는다.
P2-2. 실물 ESP32 확인 (5단계)
현재 펌웨어는 컴파일에 성공했지만(esp32dev, esp32dev_fake 모두, 2026-10-03, PlatformIO 6.2.0) 실물 시험은 하지 않았습니다. 컴파일 중 우리 코드의 경고는 확인하지 못했고, OneWire 라이브러리의 #undef 경고 2건은 있었습니다.
작업: pio run -e esp32dev_fake -t upload로 빌드·업로드하고, 시리얼에 Wi-Fi 연결됨, MQTT 연결됨, 발행 성공이 나오는지, 화면의 수온이 갱신되는지, 전원을 뽑았을 때 오프라인 알림이 뜨는지 확인한다.
필요한 것: ESP32, USB 케이블, PC의 내부망 IP, 방화벽 1883 포트 허용
완료 조건: 문서 5단계의 확인 항목이 모두 통과하거나, 실패한 곳과 오류 출력이 기록된다.
P2-3. Mosquitto 접근 제어
현재 개발용 설정은 allow_anonymous true입니다. 설정 파일 주석에도 실제 장치를 붙이기 전에 인증과 ACL로 바꾸라고 되어 있습니다.
작업: 실물 ESP32를 상시 연결하기 전에 allow_anonymous false, 비밀번호 파일, 토픽 ACL(smartfarm/<deviceId>/#)을 적용하고, Rails 구독자와 펌웨어의 자격 증명 설정(MQTT_USERNAME/MQTT_PASSWORD, secrets.h)이 동작하는지 확인한다.
완료 조건: 인증 없는 접속은 거부되고, 구독자와 ESP32는 정상 접속한다.
